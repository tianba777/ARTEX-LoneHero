# ARTEX 孤胆英豪 / ARTEX Lone Hero

基于 RuoJi6/ARTEX 的持续维护主线，选择性移植 BaaRai/ARTEX 的能力。保留原始提交历史、AGPL-3.0 许可证及原作者与贡献者署名。精确来源见 [SOURCES.json](SOURCES.json)。

## 已整合

| 能力 | 使用位置与默认行为 |
| --- | --- |
| MCP 连接状态与请求超时 | 系统 → MCP；显示最近连接结果，可分别设置远程请求超时 |
| 模型费用估算 | 系统 → 孤胆英豪；按配置设置四种 EUR / 百万 Token 单价，未定价不显示费用；历史用量按当前单价重算，不是供应商账单 |
| 任务结果与 Skill 缺口 | 系统 → 孤胆英豪；结果卡、实际调用失败统计与独立 API |
| 人工接管 | Worker 的 ask_operator 工具，附图提问、暂停意图、人工回复后继续 |
| 停滞提示 | 概览提示重复探索方向；提示不等于自动终止或证明该方向无漏洞 |
| 连续失败切换 | 默认关闭；开启后连续三次未成功的逻辑调用可推进任务链。已有输出不会重放；严格绑定的 Worker 不跨配置回退 |
| 减少重复规划 | 每任务可选，默认关闭。保留心跳监督，人工线索、目标变更、新发现与取消不会被静默丢弃 |
| 历史经验 | 默认只记录候选。注入模式仅使用已人工采纳的经验，单公司范围可复用，多公司/无公司经验留在原任务；可停用或退回候选 |
| 证据质量与不可信内容提示 | 运行时追加，保留用户自定义提示词；不把源码分析、实验或生成的请求冒充真实目标复现 |
| Ollama | 独立无密钥配置，支持连接测试、模型列表和已有模型池；保留 Ruo 的限速实现 |
| 外部浏览器流量导入 | extension/ 中的 Chromium 扩展，按操作人选择捕获并通过登录令牌导入；不是后台浏览监控 |
| 备份 | scripts/backup.sh；数据库必备份，--with-data 同时包含已有 data、skills、配置、签名密钥及 .env；本地备份含敏感材料，目录不提交 |
| 评测 | scripts/benchmark/；带独立判定与 flag 校验机制的工具，只有人工显式运行才会启动测试目标或调用模型 |
| 提交前报告复核 | scripts/submission_review/；显式运行、使用独立模型和指定规则，不自动提交报告 |

默认安装保留原有 3 个 Skills，增加 api-security、bbot-recon、codeaudit、patch-diff、rea，共 8 个。Docker 工具链加入 nuclei、httpx、subfinder、katana、ffuf、dalfox、sqlmap、bbot；原 nmap、浏览器等继续保留。rea 仍需操作人配置对应 MCP，安装 Skill 不代表 MCP 已可用。

原生 ZIP 和 Docker 镜像均附带报告复核脚本、流量捕获扩展文件、整合说明和许可证。浏览器扩展需在自己的 Chromium 浏览器中手动加载 extension 目录，再配置 ARTEX 地址和自己的登录令牌；不会自动接管浏览器。

供体的 php2shell 新近漏洞利用脚本和 edr-bypass-re 规避检测流程不纳入发行内容。供体的拒答姿态探测、自动回复 bot、删除自更新机制、重复的凭据表和模型轮转机制也不移植。Ruo 的凭据整理、Worker 池、排队/日历/运行时钟、发现归并、请求重放、拓扑、审批和更新机制保持主导。

## 部署与更新

源码模块路径维持 github.com/Autumn-27/artex，避免无意义的大面积改名。主干代码保留 Ruo 的 Go 依赖版本，未整体替换 Norma SDK。

首次构建或尚未有发行镜像时，在有 Docker 的机器准备 Linux 可执行文件后运行 docker compose build artex；完整操作沿用根 README 的构建步骤。发布后默认镜像为 ghcr.io/tianba777/artex-lonehero，私有仓库对应镜像需要有权限的账号登录 GHCR。原生发布 ZIP 包含程序与全部 Skills；外部 CLI 工具由 Docker 镜像提供，本机运行需自行准备相应工具环境。

在线更新固定指向 tianba777/ARTEX-LoneHero，禁止回退到上游发行包覆盖本项目。私有发行包可通过运行环境 ARTEX_UPDATE_TOKEN 提供本仓库 Contents 只读令牌；不存入 UI 或数据库，不写入镜像、源码与日志，且不随重定向发送到下载 CDN。开发构建不启用在线安装；没有正式 Release 时无法检查到可安装版本。

发布工作流使用 GHCR 与仓库自带 GITHUB_TOKEN，保留五平台程序包、SHA256SUMS、双架构镜像启动检查。已发布版本不可覆盖，需要发布更高版本。Demo 部署默认关闭。

## 后续同步 RuoJi6

本地首次克隆后可直接运行 scripts/sync-upstream.sh：要求工作区干净，拉取 RuoJi6/main 后创建独立同步分支，普通 merge 保留双方历史。不会 reset、rebase、强推或自动部署。发生冲突会停在同步分支，解决后检查；要放弃这次未完成的合并使用 git merge --abort。

GitHub Actions 的 sync-ruoji6 支持手工运行，成功时推送同步分支，并在仓库权限允许时创建草稿 PR；当前仓库限制 Actions 创建和审批 PR，因此保留该限制，提供比较链接由维护者创建 PR。冲突时不推送不完整合并。没有安排自动合并或定时任务。

每次同步重点复核：自更新源、镜像地址、许可证/署名、Schema 增量迁移、已有任务/提示词/凭据数据、Worker 严格绑定、日历和暂停恢复、经验采纳边界。升级前备份数据库、data、skills、配置及签名密钥；二进制回滚不会回退 Schema。

## 验证

CI 运行完整 Go 构建、vet、PostgreSQL 测试、前端类型检查与静态构建，以及评测工具的本地单元测试，不跳过已知失败项。测试使用按包隔离的数据库，模型与目标交互使用本地模拟，不运行真实目标扫描。

原基线的四处失败为旧断言/测试数据不匹配当前实现：精简概览已移除 coverage.scope、模型审查失败默认转人工及人工来源标记、日期测试缺失新增记录的时间、归档格式已升级至 v4。本项目更新相应测试契约，未放宽生产审批规则或恢复已删除的冗余上下文。

toolbox-smoke 可手工在 AMD64、ARM64 原生 runner 构建完整工具镜像，仅检查安装与命令可执行性。安装与启动检查不代表漏洞发现率、误报率或成本收益已经得到实测。
